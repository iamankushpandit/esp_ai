# conformer-stt-s3 model
The model in this folder (`model.bin`) contains a quantized and distilled version of the [nvidia/stt_en_conformer_ctc_small](https://huggingface.co/nvidia/stt_en_conformer_ctc_small) model. This project is not endorsed in any way or form by the original model authors. A copy of the original model license can be found in this folder. The following changes to the model were performed during distillation and quantization:

| Change | Explanation |
| --- | --- |
| SiLu layers were replaced by ReLu | ReLu does not require floating-point operations or lookup tables and can be applied on quantized activations directly, making it more efficient |
| power-of-two quantization | Activations, weights and biases were quantized to int8 and int32 using symmetric power-of-two quantization. Quantization is only applied for linear, convolution and fused operators. This shrinks the model size to < 16MB (to fit it into flash), allows for a more efficient usage of SIMD instructions and decreases the impact of the limited PSRAM and flash bandwidth. |
| pointwise 1D convolutions were replaced by linear layers | The pointwise convolution layers inside the conformer layers were replaced by linear layers, since they are equivalent. |
| causal 1D convolutions were replaced by 1D convolutions | The causal 1D convolutions were replaced by "normal" 1D convolutions to avoid the padding operation. |
| 4x4 kernel for the first 2D convolution | The kernel size of the first 2D convolution of the pre_encode module was increased from 3x3 to 4x4. This renders the inner matrix dimension for the underlying matrix multiplication a multiple of 16, which allows to take full advantage of SIMD acceleration. |
| bias removal of second 2D convolution | The 2D convolution operator is implemented through unfolding followed by a linear operator. To get a meaningful speedup for the linear operator, the second argument (the right-hand-side matrix for the matrix multiplication, which is typically the weight tensor) needs to be located in SRAM, since all of its elements need to be accessed to compute a single row of the result. The quantized weight tensor for this convolution exceeds the 256kb of SRAM available for model execution. Removing the bias allows to directly calculate the transposed result by swapping the activation and weight arguments for the linear operation, which now requires the activations to be in SRAM (and they fit if the chunk size is small enough). |
| bias removal of linear layer in pre_encode | same reason as above, weight tensor does not fit into SRAM. |
| fixed mean and variance for log-mel normalization | Technically not part of the model, but rather the preprocessing pipeline. The audio input is preprocessed chunk-wise, which is not possible if the mean and variance over the complete audio input needs to be calculated. Hence, a fixed mean and variance were determined by forming an average over a subset of the distillation dataset. |
